# 東煒泰和：Cloudflare 售屋與實價登錄資料查核

查核日期：2026-10-20，Asia/Taipei。

## 結論與完成範圍

目前正式站只解析售屋資料，沒有抓取社區實價登錄明細。前端顯示的「社區實登均價」「實登天花板」是依開價與固定區域參數推估；「已剔除特殊親友交易與一樓店面極端值」也沒有相對應的成交篩選流程。

本案例可做到只輸入物件網址，再自動識別正確社區並讀取實登頁。單一網址的診斷探測已成功取得社區編號 10007、實登頁總筆數 64、首批成交列 20 筆。這是可行性測試，尚未加入正式產品；Cloudflare 全量分頁抓取也尚未實作驗證。瀏覽器經正常捲動則已取得全部 64 列。

本次只新增唯讀診斷腳本與查核文件，沒有修改或重新發布正式解析流程。

## 目前程式實際如何算出「實登」

位置：專頁 `buildPropertyFromApiData()`，約第 2320 行；`regionalBenchmarks`，約第 1234 行。

本次直接以正式 API 的回傳資料執行工作區既有函式，得到：

```text
車位面積：固定假設 8.1 坪
車位價格：三重固定參數 195 萬
房屋面積：80.91 - 8.1 = 72.81 坪
開價淨單價：(5996 - 195) / 72.81 ≈ 79.6731 萬/坪
推估單價：round(((79.6731 / 1.15) × 0.65 + 62.5 × 0.35), 1)
        = 66.9 萬/坪
推估總價：round(72.81 × 66.9 + 195) = 5066 萬
```

這個 66.9 與 5066 並非成交樣本統計。沒有實際排序、剔除特殊交易、一樓或極端值；價格區間也是將推估單價乘上 0.91／1.07。以開價推算比較基準再判斷開價溢價，會產生循環比較。

兩筆頁面單價的算術平均為 `(65.1 + 73.9) / 2 = 69.5 萬/坪`；以頁面扣車位房屋價及面積作面積加權則為 `(3428 + 5080) / (52.7 + 68.7) ≈ 70.08 萬/坪`。兩種算法口徑不同，且頁面面積／價格已經四捨五入；不應混用。

這兩筆樓層、格局、面積不同，而且車位分價屬估算，因此上述數字只是計算示範，不是本案 14 樓雙車位的正式估價。樣本只有 2 筆時，不應再宣稱「去頭去尾剔除極端值」。若要求車位金額必須是已驗證的申報分價，這兩筆都不能當成已驗證的精確拆車位樣本。

## 建議修正方案

### 先處理數據誠實性

1. 刪除將開價推估值標為實登的流程。未取得成交資料時，`regPrice=null`，顯示「尚未取得實價登錄」，停止依此值產生溢價與四階出價。
2. 未取得戶數、車位價格、財務能力或實際通勤時間時，標為待確認。九把刀應使用通過／不通過／待確認，不能靠預設值通過。
3. 辨識網址種類；實登頁不能套入售屋欄位預設值。錯誤、阻擋、解析失敗、部分載入要各自揭露。

### 再加入正確的兩階段資料流程

```text
使用者只貼 sale.591.com.tw 物件網址
  → 售屋 adapter：JSON-LD + 物件本身的社區 ID、實際車位欄位
  → 社區驗證：ID + 社區名 + 行政區／地址
  → 實登 adapter：同社區 /price、後續分頁或載入介面
  → 去重、正規化、逐筆篩選
  → 成交明細與可重算統計
  → 九把刀比較與條件式出價試算
```

不得挑選物件頁任意第一個 `market.591.com.tw` 連結，因為頁面也有大量推薦社區。若沒有可驗證的社區 ID，應要求確認社區，不能自動猜配。

建議預設近三年，排除明示特殊交易；一樓應可依物件型態設定是否排除。車位分價為估算者另列，並讓使用者明確選擇是否納入參考。樣本不足時顯示資料不足，不自動加入十多年前交易湊數。可提供五年參考組，但須另外標示期間。若要採中位數、加權平均或 IQR，必須公開規則；極小樣本不做機械式去頭去尾。

在資料單位都已轉為「萬／坪」後：

```text
每筆房屋淨單價 = (含車位總價 - 車位價格) / (含車位面積 - 車位面積)
面積加權均價 = Σ(房屋價格) / Σ(房屋面積)
```

原始單位若為元／平方公尺，需先正規化，再計算。車位總價未申報或無法確認時不能直接當 0；車位估算價、申報價應分開保存。

畫面至少揭露：來源頁、擷取時間、來源總數、已擷取數、去重後數、期間篩選後數、每種剔除原因與筆數、車位估算筆數、最後採用筆數、期間、公式、明細、是否完整。例：`來源64／HTML已取20／部分資料`，或 `來源64／已取64／排特殊1／近三年2／車位估算2／參考樣本2`；不能用「來源64」充當「本次實際取得64」。

### 平台與正式資料來源

本次兩個來源經 Cloudflare API 皆可回應 HTTP 200，因此目前問題是資料流程與解析器缺漏，不是需要改主機平台。

短期可評估加入 591 實登頁解析與完整載入；長期正式統計建議使用內政部批次資料，建立更新、交易編號去重、地址正規化及社區門牌對應。政府交易資料與 591 社區 ID 沒有現成一對一鍵，仍需以門牌、建物等資訊匹配，不能只比社區名稱。

內政部批次資料是每月 1、11、21 日發布的當期靜態資料，不能稱為成交當日即時資料。來源：[官方下載頁](https://plvr.land.moi.gov.tw/DownloadOpenData)、[本期買賣資料集](https://data.gov.tw/dataset/25119)。
